# Native WeChat Mini Program Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a native WeChat Mini Program client under `miniprogram/` that runs all three quiz versions locally in WeChat DevTools and switches to CloudBase when a cloud environment ID is configured.

**Architecture:** The canonical registry and private banks remain under root `data/`. The existing build pipeline emits one public CommonJS runtime module for the native client, while private scoring stays in the local Node result service or CloudBase. A single native page renders a state machine for welcome, identity, quiz, analysis, result and share flows, using small pure modules for version context, answer state, result validation and transport selection.

**Tech Stack:** WeChat Mini Program JavaScript/WXML/WXSS, CommonJS modules, Node.js built-in test runner, existing Node local result service, WeChat CloudBase cloud functions.

## Global Constraints

- Project source and generated artifacts live under `E:\SCTI_Study`; `F:\wechat_devtools` is installation-only.
- Preserve the user's existing AppID and `project.private.config.json`; never commit AppSecret or credentials.
- `project.config.json` must point `miniprogramRoot` to `miniprogram/` and `cloudfunctionRoot` to `campus_persona/cloudfunctions/`.
- Root `data/banks/*.json`, `data/quiz-versions.v1.json` and `data/algorithms/*.json` remain the only canonical inputs.
- The native bundle must not contain scores, core mappings, private tags, algorithm profiles, target vectors or score rankings.
- Empty `cloudEnvId` means local mode; non-empty `cloudEnvId` means CloudBase mode. Cloud mode never falls back to localhost.
- Local complete testing requires `frontend-demo\npm start`; physical-device and release builds require CloudBase.
- Q20 remains self-perception-only and cannot alter the primary persona or user dimensions.
- Use TDD for every behavior change and preserve all existing tests.
