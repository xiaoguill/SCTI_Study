## 二、算法设计：答题 → 标签的完整映射逻辑

### 2.1 算法概览

采用**"核心定选题精确匹配 → 得分累积 → 四维度兜底"**的三层算法：

```
┌─────────────────────────────────────────────┐
│                 用户答题                      │
│           （20 道题，每题选 1 个选项）          │
└──────────────┬──────────────────────────────┘
               ↓
┌─────────────────────────────────────────────┐
│    第一层：核心定选题精确匹配                  │
│    每种人设有 2-3 道"核心定选题"               │
│    如果某类型的核心题全部命中 → 直接出结果      │
│    （用户不会知道哪些是核心题）                 │
└──────────────┬──────────────────────────────┘
               ↓ (无精确命中)
┌─────────────────────────────────────────────┐
│    第二层：得分累积取最高                      │
│    每个选项对 16 种类型各有 0/1/2 的得分权重    │
│    累积 20 题得分 → 取得分最高者               │
│    若最高分 ≥ 次高分 3 分 → 直接判定           │
└──────────────┬──────────────────────────────┘
               ↓ (得分最高者 < 3 分优势 or 并列)
┌─────────────────────────────────────────────┐
│    第三层：四维度兜底                          │
│    D1 学业投入度 / D2 社交活跃度              │
│    D3 自律执行力 / D4 探索开放性              │
│    计算用户四维度得分 → 匹配最近的人设画像      │
│    （曼哈顿距离最小者胜出）                    │
└─────────────────────────────────────────────┘
```

### 2.2 第一层：核心定选题精确匹配

**原理**：每种人设指定 2-3 道"核心定选题"。这些题目是该类型最具区分度的问题——但分散在不同主题的场景中，用户不会意识到它们之间存在关联。

**关键设计**：核心题的选项在表面上看起来与其他选项一样自然，用户不会意识到"选了 A 就是某个类型"。身份是通过多题组合"浮现"的。

**示例**：
- U13「食堂米其林评审员」的核心定选题 = Q7 选 D（先去吃顿好的）+ Q17 选 D（化压力为食欲）+ Q20 选 M（哪节课在食堂附近哪节课就是好课）
- 三道题分别问的是友情观、减压方式、自我写照——看起来毫无关联，但组合起来精确指向美食驱动型

### 2.3 第二层：得分累积

**原理**：每道题的每个选项，对 16 种类型分别有 0/1/2 的得分权重。2 分 = 强指向，1 分 = 弱指向，0 分 = 无关。

累积 20 题的得分后，取得分最高的类型作为结果。如果最高分比次高分多 3 分及以上，直接判定。

### 2.4 第三层：四维度兜底

如果第二层出现并列或最高分优势不够显著（<3 分），则启用四维度打分系统：

| 维度 | 低分（1-2） | 高分（4-5） | 大学版含义 |
|---|---|---|---|
| D1 学业投入度 | 大学只是跳板/体验 | 学业是生活的绝对核心 | 学业在生活中的比重和投入程度 |
| D2 社交活跃度 | 独狼/宿舍宅/隐身 | 社交达人/人脉编织者 | 校内外的社交能力和活跃度 |
| D3 自律执行力 | 拖延/摸鱼/混乱/随性 | 自律/高效/计划性强 | 自我管理和执行效率 |
| D4 探索开放性 | 深耕一个方向/求稳 | 多线并行/跨界/尝新 | 对新事物/跨领域的开放度 |

每种人设在四维度上有标准画像（目标向量），计算用户实际得分与每种人设画像的**曼哈顿距离**，取最近的。

### 2.6 四维度计算方法

每道题的每个选项隐含四维度分值（1-5 分），用户在 20 题上的选择累积后取平均值，得到用户的四维度实际得分向量 (d1, d2, d3, d4)。

然后计算用户向量与每种人设标准向量的**曼哈顿距离**：

```
Distance = |d1 - t1| + |d2 - t2| + |d3 - t3| + |d4 - t4|
```

取距离最小的人设作为最终结果。

## 六、设计说明

### 6.1 "隐性身份探测"的核心设计思路

**传统测试的问题**：大多数测试的题目有明显的导向性。比如直接问"你周末一般在哪儿？A.图书馆 B.宿舍 C.社团 D.校外"——用户一看就知道选 A 就是"学霸"，选 B 就是"宅人"，毫无惊喜感。

**V5 的解决方案**：身份是"浮现"的，不是"被问出"的。

具体实现方式：

**① 同一探测维度用不同场景包装**

以"精力投向"这个隐性维度为例，它被拆进了 5 道不同的题：

| 题号 | 表面问题 | 实际探测 |
|---|---|---|
| Q1 | 周末早上 9 点你在哪 | 精力投向（通过行为暗示） |
| Q4 | 期末备考状态 | 精力投向（通过复习计划暗示） |
| Q9 | 5000 块怎么用 | 精力投向（通过花钱方向暗示） |
| Q11 | 对恋爱的态度 | 精力投向（通过优先级暗示） |
| Q18 | 毕业后打算 | 精力投向（通过未来规划暗示） |

**用户在做 5 道不同的题时，不会意识到它们都在探测同一件事。**

**② 标签通过多题组合定位**

以"U13 食堂米其林评审员"为例，它的定位需要以下信号组合：

```
Q2 选 D（在想早餐吃什么）→ 可能只是馋，也可能真的是吃货
Q4 选 C（什么是期末？）→ 可能是不在意学业，也可能是自信
Q7 选 D（先去吃顿好的）→ 强指向！朋友挂科第一反应是吃
Q8 选 B（情景喜剧）→ 轻松快乐的生活态度
Q9 选 B（请朋友吃饭）→ 花钱第一反应是吃
Q13 选 D（没去过）→ 可能是不想上课，也可能是去找吃的了
Q17 选 D（找不到人一起吃饭）→ 弱指向
Q20 选 M（食堂附近=好课）→ 决定性！

→ 多道题的信号叠加，"食堂米其林评审员"的身份自然浮现
```

**③ 没有任何一题是"送分题"**

每道题的选项都设计成"用户选的时候觉得这只是在描述我的生活"，而不是"选了这个就被定位成某类型"。例如：

- Q2 闹钟题：选"在想早餐吃什么"的人觉得"我确实会想吃什么啊"，不会想到这和"食堂米其林评审员"有关
- Q7 友情观题：选"先去吃顿好的"的人觉得"我就是这种安慰朋友的方式"，不会想到这直接指向美食驱动型
- Q8 电影类型题：选"情景喜剧"的人觉得"我大学确实挺搞笑的"，不会想到这暗示"轻松快乐的生活态度+美食驱动"


### F.1 数据结构

```
// 标签定义
interface Tag {
  id: string;        // "U1" ~ "U16"
  name: string;      // "绩点纺织工"

}

interface CoreQuestion {
  questionId: number; // 题号
  answerIndex: number; // 选项索引（0-3）
}

// 题目定义
interface Question {
  id: number;
  text: string;        // 题干
  type: 'normal' | 'rhythm_break'; // 题目类型

}

interface Option {
  text: string;        // 选项文本
  scores: Record<string, number>; // 对16种类型的得分 {"U1": 2, "U2": 0, ...}
  dimensions: [number, number, number, number]; // 四维度分值
  easterEgg?: string;  // 彩蛋文本（节奏破坏题专用）
}

// 用户答题结果
interface UserAnswer {
  questionId: number;
  answerIndex: number;
}

// 结果
interface Result {
  tagId: string;
  tagName: string;
  tagDesc: string;
  dimensions: [number, number, number, number]; // 用户实际四维度
  radarData: Record<string, number>; // 雷达图数据
```

### F.2 算法伪代码

```
function calculateResult(answers: UserAnswer[]): Result {
  // 第一层：核心定选题精确匹配
  for (tag of allTags) {
    if (tag.coreQuestions.length === 0) continue;
    let allMatch = true;
    for (core of tag.coreQuestions) {
      const answer = answers.find(a => a.questionId === core.questionId);
      if (!answer || answer.answerIndex !== core.answerIndex) {
        allMatch = false;
        break;
      }
    }
    if (allMatch) {
      return buildResult(tag, 'core', answers);
    }
  }

  // 第二层：得分累积
  const scores = {};
  for (answer of answers) {
    const option = questions[answer.questionId].options[answer.answerIndex];
    for (tagId of allTagIds) {
      scores[tagId] = (scores[tagId] || 0) + (option.scores[tagId] || 0);
    }
  }
  
  const sorted = Object.entries(scores).sort((a, b) => b[1] - a[1]);
  if (sorted[0][1] - sorted[1][1] >= 3) {
    return buildResult(getTag(sorted[0][0]), 'score', answers);
  }

  // 第三层：四维度兜底
  const userDims = calculateUserDimensions(answers);
  let minDist = Infinity;
  let bestTag = null;
  for (tag of allTags) {
    const dist = manhattanDistance(userDims, tag.dimensions);
    if (dist < minDist) {
      minDist = dist;
      bestTag = tag;
    }
  }
  return buildResult(bestTag, 'dimension', answers);
}

function manhattanDistance(a: number[], b: number[]): number {
  return a.reduce((sum, v, i) => sum + Math.abs(v - b[i]), 0);
}
```

### F.3 性能考量

- 20 题 × 16 类型 = 320 个得分计算，性能无忧
- 核心定选题检查最多 16 × 3 = 48 次比较
- 四维度计算最多 16 次曼哈顿距离
- 总计算量极小，可在客户端实时完成，无需后端
