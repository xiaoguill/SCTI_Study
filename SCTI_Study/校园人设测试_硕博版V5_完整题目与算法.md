## 二、算法设计：答题 → 标签的完整映射逻辑

### 2.1 算法概览

采用**"核心定选题精确匹配 → 得分累积 → 四维度兜底"**的三层算法：

```
┌─────────────────────────────────────────────┐
│                 用户答题                      │
│           （20 道题，每题选 1 个选项）          │
└──────────────┬──────────────────────────────┘
               ↓
┌─────────────────────────────────────────────┐
│    第一层：核心定选题精确匹配                  │
│    每种人设有 2-3 道"核心定选题"               │
│    如果某类型的核心题全部命中 → 直接出结果      │
│    （用户不会知道哪些是核心题）                 │
└──────────────┬──────────────────────────────┘
               ↓ (无精确命中)
┌─────────────────────────────────────────────┐
│    第二层：得分累积取最高                      │
│    每个选项对 16 种类型各有 0/1/2 的得分权重    │
│    累积 20 题得分 → 取得分最高者               │
│    若最高分 ≥ 次高分 3 分 → 直接判定           │
└──────────────┬──────────────────────────────┘
               ↓ (得分最高者 < 3 分优势 or 并列)
┌─────────────────────────────────────────────┐
│    第三层：四维度兜底                          │
│    D1 学术投入度 / D2 社交活跃度              │
│    D3 自律执行力 / D4 探索开放性              │
│    计算用户四维度得分 → 匹配最近的人设画像      │
│    （曼哈顿距离最小者胜出）                    │
└─────────────────────────────────────────────┘
```

### 2.2 第一层：核心定选题精确匹配

**原理**：每种人设指定 2-3 道"核心定选题"。这些题目是该类型最具区分度的问题——但分散在不同主题的场景中，用户不会意识到它们之间存在关联。

**关键设计**：核心题的选项在表面上看起来与其他选项一样自然，用户不会意识到"选了 A 就是某个类型"。身份是通过多题组合"浮现"的。

**示例**：
- G13「白大褂战士」的核心定选题 = Q3 选 B（微信步数 15000）+ Q7 选 B（暑假在医院值班）+ Q17 选 B（毕业后想进三甲）
- 三道题分别问的是步数、暑假安排、毕业打算——看起来毫无关联，但组合起来精确指向规培医学生

### 2.3 第二层：得分累积

**原理**：每道题的每个选项，对 16 种类型分别有 0/1/2 的得分权重。2 分 = 强指向，1 分 = 弱指向，0 分 = 无关。

累积 20 题的得分后，取得分最高的类型作为结果。如果最高分比次高分多 3 分及以上，直接判定。

### 2.4 第三层：四维度兜底

如果第二层出现并列或最高分优势不够显著（<3 分），则启用四维度打分系统：

| 维度 | 低分（1-2） | 高分（4-5） | 硕博版含义 |
|---|---|---|---|
| D1 学术投入度 | 读研只是中转站 | 学术就是全部 | 学术在生活中的比重 |
| D2 社交活跃度 | 独狼/隐身 | 社交达人/人脉广 | 学术圈内外社交能力 |
| D3 自律执行力 | 摸鱼/拖延/混乱 | 自律/高产/高效 | 自我管理和产出效率 |
| D4 探索开放性 | 深耕一个方向 | 跨领域/多线并行 | 对新事物/跨界的开放度 |

每种人设在四维度上有标准画像（目标向量），计算用户实际得分与每种人设画像的**曼哈顿距离**，取最近的。

## 六、设计说明

### 6.1 "隐性身份探测"的核心设计思路

**传统测试的问题**：大多数测试的题目有明显的导向性。比如直接问"你周末一般在哪儿？A.实验室 B.医院 C.实习公司"——用户一看就知道选 C 就是"实习打工人"，毫无惊喜感。

**V5 的解决方案**：身份是"浮现"的，不是"被问出"的。

具体实现方式：

**① 同一探测维度用不同场景包装**

以"物理位置"这个隐性维度为例，它被拆进了 6 道不同的题：

| 题号 | 表面问题 | 实际探测 |
|---|---|---|
| Q1 | 周五下午的自由时间 | 物理位置（通过行为暗示） |
| Q2 | 早上闹钟响了去哪 | 物理位置（通过早起目的地暗示） |
| Q3 | 微信步数 | 物理位置（通过步数暗示） |
| Q7 | 暑假安排 | 物理位置（通过暑假在哪暗示） |
| Q9 | 校园偶遇同行 | 物理位置（通过"好久没来"暗示） |
| Q13 | 国庆假期 | 物理位置（通过假期状态暗示） |

**用户在做 6 道不同的题时，不会意识到它们都在探测同一件事。**

**② 标签通过多题组合定位**

以"G13 白大褂战士"为例，它的定位需要以下信号组合：

```
Q2 选 B（赶早班）→ 可能是在医院，也可能只是早起
Q3 选 B（15000 步）→ 可能是医生，也可能只是爱走路
Q4 选 B（简洁回复）→ 可能是忙，也可能只是话少
```
